---
title: pun composer
description: Run other Composer commands.
---

Run Composer commands that have no `pun` command of their own: `dump-autoload` and `validate`.

## Usage

```bash
pun composer <command> [options]
```

```bash
pun composer dump-autoload
pun composer dump-autoload -o --no-dev
pun composer validate
pun composer validate --strict --with-dependencies
```

## Options

For `dump-autoload` (alias `dumpautoload`):

| Option | Description |
| --- | --- |
| `-o`, `--optimize` | Add PSR-0 and PSR-4 classes to the class map. |
| `-a`, `--classmap-authoritative` | Load classes from the class map only. |
| `--apcu` | Cache class lookups in APCu. |
| `--apcu-prefix=<prefix>` | The APCu prefix. |
| `--dev` | Include `autoload-dev`. |
| `--no-dev` | Skip `autoload-dev` and dev packages. |
| `--no-scripts` | Skip the root package's scripts. |
| `--no-plugins` | Skip Composer plugins. |
| `--ignore-platform-req=<req>` | Leave one requirement out of `platform_check.php`. |
| `--ignore-platform-reqs` | Write no `platform_check.php`. |
| `-d`, `--working-dir=<dir>` | Run in `<dir>`. |

For `validate`:

| Option | Description |
| --- | --- |
| `[file]` | The `composer.json` to check (default: `COMPOSER`, else `./composer.json`). |
| `--no-check-all` | Skip the warnings for unbound (`*`, `>=1.0`) and exact (`1.2.3`) constraints. |
| `--check-lock` | Check `composer.lock` even when `config.lock` is false. |
| `--no-check-lock` | Report a stale `composer.lock` as warnings, not errors. |
| `--no-check-publish` | Skip what only stops the package from being published. |
| `--no-check-version` | Skip the warning for a `version` field. |
| `-A`, `--with-dependencies` | Also check `vendor/<name>/composer.json` of every installed package. |
| `--strict` | Exit 1 for warnings too. |
| `-d`, `--working-dir=<dir>` | Run in `<dir>`. |

## What happens

`dump-autoload`:

- Writes the autoloader again from `vendor/composer/installed.json`.
- The files match `composer dump-autoload` byte for byte.
- Runs the autoload scripts and allowed plugins.
- Without `--dev` or `--no-dev`, follows the last install.
- Pun never calls the Composer CLI.

`validate`:

- Checks `composer.json` as `composer validate` does, with the same messages: the JSON syntax (the same parse errors), Composer's JSON schema (what only the strict schema refuses is a publish error), and Composer's own checks of names, versions, constraints, licenses (SPDX), URLs, authors, autoload and the rest.
- Checks that `composer.lock` is up to date and has every requirement.
- A `composer.json` that Composer can't load (a parse error, a value the schema refuses, a package requiring itself) is an error, not a report.

## Limitations

- Only `dump-autoload` and `validate` exist. Any other command exits 2.
- `validate` reads `time` in the forms Composer documents (`YYYY-MM-DD`, `YYYY-MM-DD HH:MM:SS`) and ISO 8601's, and reports no error for any other value or for an impossible date in those forms (`2020-13-01`). Composer reports a value PHP's `DateTime` can't parse.
- When a JSON parse error's excerpt cuts a multibyte character in two, `validate` prints `�` where Composer prints the partial byte.
- `validate` sends no `command` event to Composer plugins, so a plugin can't change its exit code.
- Where Composer itself crashes on a value of the wrong type (a number as a constraint, a list mixing licenses and numbers), `validate` reports what Composer reports without the crash.

## Exit codes

| Code | Meaning |
| --- | --- |
| 0 | Written, or valid (warnings allowed). |
| 1 | Written, but a package is missing from `vendor/`; or `validate --strict` found warnings. |
| 2 | Unknown command; `validate` found errors (publish and lock errors included, unless left out by an option); or another error. |
| 3 | `validate`: the `composer.json` is missing or unreadable. |
